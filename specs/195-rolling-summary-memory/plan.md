# Implementation Plan: Rolling Summary Memory (v2 — Context Injection)

**Branch**: `195-rolling-summary-memory` | **Date**: 2026-04-07 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/195-rolling-summary-memory/spec.md`

## Summary

Add an in-agent rolling memory buffer that splits incoming conversation into two segments — a **recent window** (newest turns within a token budget) and **older history** (everything before). The older history is summarized by an LLM call, and the agent's context is rewritten to `[system prompt] → [summary message] → [recent window]`, replacing the full raw conversation. Both the summary text and recent message objects are returned on REST and MCP responses. Off by default, fail-open with fallback to full messages.

## Design Decisions

### D1: Context Rewriting via task_messages

Modify `self.task_messages` on `BaseAgent` before the reasoning loop. `_prepare_context()` (line 197) uses `self.task_messages` directly, so all agent subclasses automatically get compacted context without changes. Original messages preserved in `self._original_task_messages` for response assembly and fail-open fallback.

### D2: Summary as System Message

The summary is injected as `{"role": "system", "content": "[Conversation history summary]: ..."}` between the original system messages and the recent window. This positions it as context rather than a conversational turn.

### D3: Sequential Summarization Only

The `parallel_with_first_iteration` option is removed. Since context injection requires the summary before the first iteration, parallel execution is incompatible. Summarization latency (~200-800ms) is accepted as the cost of context compaction.

### D4: Fail-Open Fallback to Full Messages

On summarization failure, `self.task_messages` is restored from `self._original_task_messages`. The agent proceeds with the full conversation. Summary response fields are omitted.

### D5: Config Dict Coercion

Same pattern as v1 fix — check if `memory` is a dict from the cascade and coerce to `RollingSummaryConfig`.

### D6: Response Field Assembly

Both `conversationSummary` and `recentMessages` are stored on `AgentContext` and read by both the REST endpoint (SSE metadata event) and MCP server (AskResponse JSON).

## Complexity Tracking

No constitution violations. The context modification is to input data (`task_messages`), not to the execution machinery (`_prepare_context`, reasoning loop, action phases).
